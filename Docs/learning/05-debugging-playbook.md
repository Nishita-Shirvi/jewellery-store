# 05 — Debugging playbook

First, always: **(1)** check the `app.start` log line (what's switched on), **(2)** find the log lines for the order/user/time, **(3)** look at the rows in Prisma Studio. See `../LOGGING.md`.

## App won't start / build fails

| Symptom                                                          | Cause                                                                      | Fix                                                                                                       |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `❌ Invalid or missing environment variables`                    | `.env` / Vercel env missing or wrong                                       | Message names the variable. Compare with `.env.example`. On Vercel: set it, then **Redeploy**.            |
| `❌ Invalid settings in config/*.ini`                            | Bad value in a `config/*.ini` file (or an env override)                    | Message names `[section] key`. See `../CONFIGURATION.md`.                                                 |
| `❌ [x] is defined in both config/a.ini and config/b.ini`        | Same section in two files                                                  | Keep the section in one file.                                                                             |
| Changed a `config/*.ini` value, nothing happened                 | Misspelled key (ignored silently), an env override, or no restart/redeploy | Check the key name against `CONFIGURATION.md`; `app.start` → `configOverriddenByEnv`.                     |
| `❌ Unsafe production settings`                                  | Production only (`VERCEL_ENV=production`)                                  | `NEXT_PUBLIC_APP_URL` must be the live `https://` URL, `CRON_SECRET` set, no `*_API_BASE` test overrides. |
| Build log: `Skipping prisma migrate deploy` on production        | `VERCEL_ENV` isn't `production` for that build                             | Expected on previews. For a preview with its own DB set `RUN_MIGRATIONS=1`.                               |
| `The table "public.Review" does not exist` (or any table/column) | Migrations not applied to that DB                                          | `npm run db:deploy` (production) / `npm run db:migrate` (local). Check `prisma/migrations` is committed.  |
| `Can't reach database server` / health returns 503               | DB down, wrong URL, Neon paused                                            | Check `DATABASE_URL`; Neon free tier wakes up on first request — retry.                                   |
| Prisma "Unknown field" type errors after pulling                 | Prisma client out of date                                                  | `npm install` (runs `prisma generate`) or `npm run db:generate`.                                          |

## Payments

| Symptom                                      | Where to look                                                                               | Likely cause                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "Online payments are not set up yet"         | `app.start` → `razorpay: false`                                                             | One of the three `RAZORPAY_*` vars missing.                                                                                                                                                                                                                                                                                               |
| Customer paid, order still PENDING/FAILED    | Logs: `payment.` + order id; `Payment` row; Razorpay dashboard → webhook deliveries         | Webhook URL/secret wrong in Razorpay (look for `webhook.razorpay_bad_signature`) **and** the popup callback didn't complete. Fix the webhook, then use Razorpay's "resend" on that event — processing is idempotent.                                                                                                                      |
| `payment.amount_mismatch`                    | `Payment.amountInPaise` vs `Order.totalInPaise`                                             | Order total changed after the Razorpay order was created — investigate before touching data.                                                                                                                                                                                                                                              |
| `payment.sold_out_after_payment_refunding`   | Order REFUND_PENDING + Refund row (same transaction)                                        | Expected: customer paid after their hold expired and the piece was sold. Refund goes out automatically; if the Razorpay call was lost, the cron sweep or **Retry refund** sends it.                                                                                                                                                       |
| `payment.extra_payment_refunding`            | `Payment` row with `providerOrderId` starting `extra:` + its Refund                         | Expected: a second payment for an already-paid order, or a payment for a cancelled order. Refunded in full automatically — do **not** also refund it in the Razorpay dashboard.                                                                                                                                                           |
| Paid twice for one cart                      | `Order.checkoutKey`, logs `payment.duplicate_payment_id`, `payment.extra_payment_refunding` | The second payment is refunded automatically (above). If you see two payments without an `extra:` row, file a bug with both payment ids.                                                                                                                                                                                                  |
| Refund stuck "in progress"                   | `Refund.status`, `failureReason`, `updatedAt`; logs `refund.`                               | Razorpay failed (`refund.failed_to_send`) → admin order page → **Retry refund**. PENDING with no `razorpayRefundId` for 10+ min = never sent: Retry, or wait for the cron (`refund.stuck_swept`). `failureReason = "Sending to Razorpay…"` = a sender is on it right now. Or the `refund.processed` webhook isn't subscribed in Razorpay. |
| `refund.processed_for_other_razorpay_refund` | Both Razorpay refund ids in the log                                                         | Money may have gone out twice for one refund row — check in the Razorpay dashboard and reconcile by hand.                                                                                                                                                                                                                                 |

## Stock

| Symptom                                         | Where to look                                                    | Likely cause / fix                                                                                                                                                                                      |
| ----------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Product shows "out of stock" but stock > 0      | `Product.reservedStock`; orders with `reservationState = ACTIVE` | Holds not released: `CRON_SECRET` not set or cron not running (`cron.unauthorized`, 503). Holds are also released at every checkout start. Call `/api/cron/release-reservations` with the bearer token. |
| Stock went negative / oversold                  | `tests/db/reservation.test.ts`                                   | Should be impossible; someone changed stock outside `inventory.service.ts`.                                                                                                                             |
| Admin changed stock but shop shows old value    | Cache (`CATALOG_TAG`)                                            | Changes made via admin revalidate instantly; changes made directly in DB show after ≤5 min.                                                                                                             |
| "Stock changed while you were editing"          | Product edit form                                                | Someone bought (or another admin edited) since the form was opened. Reload and re-enter.                                                                                                                |
| "Please choose a size." / cart line unavailable | `Product.sizes`, `CartItem.size`                                 | The piece has sizes and none (or a removed one) was picked. Sizes share stock: two sizes of one piece count together.                                                                                   |

## Gold rates and prices

| Symptom                                            | Check                                                                                                                                                                                                       |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rate-linked price didn't change after saving rates | Product `pricingMode` must be RATE_LINKED and its `purity` must match the rate saved; log `metal_rates.saved` shows `repriced`. Rate entered equal to the current one = nothing saved ("No rate changed."). |
| "No 22K rate yet…" when saving a product           | No `MetalRate` row for that purity: Admin → Gold rates first, or use a fixed price.                                                                                                                         |
| Price breakup missing on product page              | Shown only for RATE_LINKED pieces when the stored price equals the calculation with today's rate (e.g. a product edited after a rate change without a re-save shows no breakup until the next rate save).   |
| Dashboard "Metal rates are older than … hours"     | A purity used by rate-linked products has no rate, or its newest rate is older than `[pricing] stale_after_hours`. Saving the **same** rate again doesn't refresh the date (no new row).                    |
| Rate bar not showing                               | `[features] rate_strip`, `[pricing] strip_purities`, and a rate saved for at least one of those purities.                                                                                                   |

## Emails, SMS, images, shipping, login

| Symptom                                                      | Check                                                                                                                                                                                                             |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No emails arrive                                             | `app.start` → `email: false` → set `RESEND_API_KEY`. Log `email.skipped_no_api_key` means it was only logged. Resend test domain only delivers to the account owner's address — verify your domain (`DEPLOY.md`). |
| No SMS                                                       | Needs `[features] sms = true` **and** `MSG91_*` keys **and** a DLT template.                                                                                                                                      |
| Admin can't upload photos                                    | `config/images.ini` → `provider`; its keys (`CLOUDINARY_*`, or `R2_*` + `r2_public_url`). Log `upload.failed` has the provider's error. Max `[images] max_upload_mb` (5 MB), JPG/PNG/WebP.                        |
| "Images must be uploaded files or /images/... paths" on save | The link isn't from **our** Cloudinary cloud or R2 address (`lib/media.ts`). After switching to R2, keep `CLOUDINARY_CLOUD_NAME` set so old Cloudinary photos stay valid.                                         |
| WhatsApp button / visit page missing                         | `[features] whatsapp_button` + a WhatsApp number in Admin → Settings; `[features] visit_booking`.                                                                                                                 |
| No visit alert email                                         | Logs `visit.requested` then `visit.alert_failed`; recipients = `[alerts] admin_email` or all admins. The request is saved anyway (Admin → Visits).                                                                |
| "Create shipment" fails                                      | `Shipment.lastError` on the order; logs `shipment.`. Pickup location name must match Shiprocket exactly (`SHIPROCKET_PICKUP_LOCATION`). Press again — it resumes.                                                 |
| Tracking never updates                                       | Shiprocket webhook URL + token; logs `webhook.courier_bad_token`.                                                                                                                                                 |
| "Too many login attempts"                                    | In-memory limits per 15 min: 5 per email+IP, 30 per IP, 20 per account from any IP. Wait, or restart (dev).                                                                                                       |
| Invoice not created                                          | Log `invoice.skipped_business_details_incomplete`: `config/business.ini` still has `[placeholders]`. Fill in, deploy, press **Generate invoice**.                                                                 |
| Google button missing                                        | `AUTH_GOOGLE_ID/SECRET` not set — expected.                                                                                                                                                                       |
| Admin gets "forbidden"                                       | `User.role` must be ADMIN in the DB **and** the user must log out/in to refresh the cookie.                                                                                                                       |

## Money / tax looks wrong

| Symptom                                | Check                                                                                                                                                                                              |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Wrong shipping fee                     | `config/shipping.ini [shipping]` (or `SHIPPING_FEE_RUPEES` override). Free threshold uses the subtotal **before** coupon. Logic: `lib/shipping-fee.ts`.                                            |
| IGST instead of CGST+SGST (or reverse) | `config/business.ini [business] state` vs the customer's address state at checkout — must be the exact official name. `lib/gst.ts` → `isIntraState`. Invoices reuse the split stored on the order. |
| Coupon rejected                        | Message tells which rule; rules in `lib/coupons.ts`, limits in `services/coupon.service.ts`.                                                                                                       |
| Old invoice shows old business name    | By design: invoices are frozen at payment time.                                                                                                                                                    |

## When you can't find it

1. Get the exact URL → open `app/<url>/page.tsx` → follow imports into `services/`.
2. Search the repo for the user-visible error text — every message is a string in the code.
3. Search for the log event name.
4. Use `02-feature-map.md`.
5. Reproduce in a test (copy the closest existing test in `tests/`), then fix, then `npm run verify`.
